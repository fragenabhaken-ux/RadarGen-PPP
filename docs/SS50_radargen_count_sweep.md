# RadarGen SS50 count sweep

Output: `output/paper_material/count_sweep_evaluation/ss50_radargen_count_sweep/`.

This experiment holds RadarGen's predicted maps and IRL1 optimization settings fixed, then varies a single final recovery threshold shared across all 50 frames. It targets realized mean point counts 100–2000 in steps of 100. Counts remain scene-dependent. Thresholds are calibrated from the pooled positive optimized amplitudes; equal-amplitude ties are retained or excluded together, choosing the nearest attainable mean. A target above the mean number of positive cells is reported unavailable rather than forcing extra detections.

Recovery uses the repository's exact standalone `pcl_recovery.py` implementation: normalize each density map by its maximum, Gaussian sigma 2 pixels, lambda 0.0018, five IRL1 reweightings, up to 300 FISTA iterations each. Optimization is run once per frame and cached as NPZ. Final strict thresholding retains every cell above the shared threshold. There is no local-maximum suppression. Each retained cell yields one point at its center, RCS is rounded, and Doppler is read directly at the selected cell, matching the normal recovery code. No PPP metrics apply to these maps.

The frame identities/order match the DINO SS50 sweep. Continuous GT arrays are checked for exact equality across archived preprocessing paths and both historical reference evaluations. Predictions come from the completed `FULL_validation_20261108/radargen/predictions.h5` archive. The full-validation per-sample RNG indices differ from the original SS50 run, so archived maps may differ from historical SS50 maps. Accordingly the threshold 0.1 native baseline is evaluated on the same fixed maps as this sweep; historical RadarGen metrics are explicitly labeled separately. CPU FFT numerical differences from archived GPU recovery can also affect near-threshold cells; native and archived per-frame counts are saved in `experiment.json`.

One evaluation is sufficient per threshold because recovery is deterministic for fixed maps. This does not estimate diffusion-seed variation. All point-cloud/foreground/class MMD metrics reuse existing evaluation code and empty-cloud handling. Field-based mark errors are evaluated at GT locations and remain unchanged across thresholds. The existing DINO sweep curve is included in each of the ten individual PNG plots for comparison.

Launch: `bash jsc_jupiter/SS50_radargen_count_sweep_entry.sh`. Runs on the entry node at reduced priority, 24 CPU workers and one BLAS/PyTorch thread per worker, no GPU. Live log: `entry.log`. Results: `results.md`, `results.csv`, `plots/README.md`; actual recovery visualization: `recovery_example.png`; timing and process CPU/memory: `timing.json`, `resource_usage.json`.
